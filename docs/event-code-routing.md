# Event-code route candidate

This patch wires a candidate code-entry page at /events/[slug]/access, event-pass presentation/guide checks, a pass-only PDF download API and the existing video endpoint. The switch COMMONWORK_EVENT_CODE_ACCESS_ENABLED must be exactly true; leave it unset until staging setup and tests are approved. With it unset the existing signed-in event path remains. With it enabled the event landing redirects to the code hub; existing manager pages remain gated and signed-in approved access remains an alternative for the protected presentation/video paths. This does not add public membership signup.

Required staging setup, separately authorized: apply the foundation migration, configure a hashed code record for a published event, add an independently generated COMMONWORK_EVENT_PASS_SIGNING_SECRET (at least 32 random bytes), and ensure COMMONWORK_VIDEO_SECRET_KEY belongs to the same project as PUBLIC_SUPABASE_URL. These values are server-only. No real code, secret, email, database change or deployment is created by committing this patch.

Pass authorization reloads current published-event/code state for every protected request. Downloads resolve material IDs only within the authorized event and use the existing private streaming/path validation. Direct legacy /api/events/material downloads keep their existing authenticated checks; the code hub uses /api/events/code-material. Event passes do not create Auth users, profiles, attendance or workspace memberships.

Redemption accepts same-origin URL-encoded POSTs of at most 4096 bytes. Before code hashing, service-only database RPCs limit attempts to 100 per event per 10 seconds and 60 per adapter-provided client IP per minute. The IP is HMAC-hashed, not stored or logged. Shared conference IPs may require limits to be tuned after testing. Verify clientAddress behavior on the real Vercel adapter before activation. Add bounded expired-attempt cleanup before launch. Signed passes last at most 24 hours and use HttpOnly/SameSite=Lax cookies, Secure on HTTPS.

Optional email updates are NOT implemented by this patch. A separate consent/subscription/withdrawal patch is required; do not claim newsletter registration is available. Existing public Insights/reviews and private workspace behavior are unchanged.

Tests added here are form-parser, route-boundary and disabled-access checks, not a successful live event-code journey or database concurrency test. Run npm run check, npm run build and the event-pass, event-code-routing, event-video-boundaries and event-object-delivery Playwright suites; inspect existing credential-isolation tests too. Test code entry without sign-in, expired/incorrect/disabled/rotated codes, cross-event tokens/materials, throttling, secure cookies, PDF delivery, all videos and seeking, signed-in legacy access and management/workspace denial. Do not merge or deploy Production until checks pass and the optional subscription requirement is completed or explicitly deferred.
